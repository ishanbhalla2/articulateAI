# ArticulateAI: session feedback app

A participant gives a short talk, one or more judges give spoken feedback, and the app turns both into structured, evidence-based feedback across 10 categories.

Workspace: `vivanti` profile (`adb-7405609040922704.4.azuredatabricks.net`). Every resource uses the `articulate-ai-ib` / `articulate` prefix and carries the tags `project=articulate-ai`, `owner=ishan.bhalla@vivanti.com` and `env=dev`.

## What lives where

| Piece | Location |
|---|---|
| Web app (AppKit, React/TypeScript) | `articulate-ai-ib/` → app `articulate-ai-ib` |
| Processing job (Python, serverless) | `articulate-ai-ib/processing/` → job `[articulate-ai-ib] process-session` |
| Job definition | `articulate-ai-ib/resources/process_session.job.yml` (same bundle as the app) |
| Feedback and classification prompts | `articulate-ai-ib/processing/prompts/` (versioned, e.g. `feedback_v1`) |
| Lakebase schema and seed data | `setup/lakebase/*.sql` → project `articulate-ai-ib`, database `databricks_postgres`, schema `articulate` |
| Delta analytics table | `setup/delta/feedback_scores.sql` → `articulate_ai_ib.articulate.feedback_scores` |
| Media | Volume `articulate_ai_ib.articulate.media`: `raw/` (uploads as chunks), `audio/`, `frames/`, `transcripts/` |
| Synthetic test session | `sample_session/` (text-to-speech recordings: participant + 2 judges) |

## Common tasks

```bash
# Deploy app + job (from articulate-ai-ib/)
databricks apps deploy --profile vivanti

# Apply Lakebase migrations (runs every NNN_*.sql in order; all statements are idempotent)
python setup/lakebase/apply.py --profile vivanti

# Re-grant the app's service principal access to the Lakebase schema (after recreating the app)
python setup/lakebase/grant_app.py --profile vivanti --app articulate-ai-ib

# Tests
(cd articulate-ai-ib && npm test)                 # app
(cd articulate-ai-ib/processing && pytest tests)  # job rules (needs psycopg, databricks-sdk, pytest)
```

The `setup/lakebase` scripts need `psycopg[binary]` and `databricks-sdk`.

## Pipeline

`prepare_media → transcribe → delivery_metrics → classify_domain → generate_feedback → persist`, plus `mark_failed` when any step fails. Each step updates `sessions.status` and `current_step`, which the app polls.

- **Transcription:** faster-whisper (`small`, CPU, int8) with word timestamps. Audio is decoded with the bundled ffmpeg (`imageio-ffmpeg`).
- **Feedback:** the provider, model and depth come from the session's `settings_snapshot`.
- **Video:** with an image-capable model at depth 3 or above, sampled frames from the participant's video are sent to the model.
- **Checked in code:** exactly 10 categories, whole-number scores from 1 to 5, and every quote found word for word in the transcript (its timestamp is corrected from word timings). Delivery metrics are measured, never generated by the model.

## Raw media retention

There is no retention policy yet. A clean-up of `raw/<session_id>/` once `audio/` exists, or after N days, would plug into the end of the `persist` step.
