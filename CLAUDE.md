# ArticulateAI

A session feedback app. A participant gives a short talk, judges give spoken feedback, and a processing job turns both into structured, evidence-based feedback across 10 categories. It runs as a Databricks App plus a serverless job, deployed from one bundle.

See @README.md for what lives where, the pipeline steps and common commands. The app's AppKit guidance is in [articulate-ai-ib/CLAUDE.md](articulate-ai-ib/CLAUDE.md).

## Layout

- `articulate-ai-ib/`: the bundle root (`databricks.yml`). It contains the app and the job.
  - `client/src/`: React frontend (pages, components, `lib/api.ts`, `lib/upload.ts`)
  - `server/`: Express backend on AppKit (`routes/*-routes.ts`, `lib/db.ts`, `lib/processing.ts`, `lib/identity.ts`)
  - `shared/domain.ts`: types and rules shared by client and server
  - `processing/`: Python job. `run_step.py` is the entry point and `articulate_job/` holds one module per step. Prompts are in `prompts/*_vN.md`.
  - `resources/process_session.job.yml`: job definition
- `setup/lakebase/`: numbered, idempotent SQL migrations (`NNN_*.sql`), plus `apply.py` and `grant_app.py`
- `setup/delta/`: Delta analytics table DDL
- `sample_session/`: synthetic test talk and judge recordings

## Commands

Run these from `articulate-ai-ib/` unless noted:

```bash
npm run dev            # local dev server (needs .env; see .env.example)
npm run typecheck
npm run lint
npm run format
npm test               # vitest
(cd processing && pytest tests)
databricks apps deploy --profile vivanti                    # deploy app + job
python setup/lakebase/apply.py --profile vivanti            # from repo root
```

Before calling a change done, run `typecheck`, `lint` and `test` for the TypeScript side, and `pytest` if `processing/` changed.

## Databricks workspace rules

- The workspace (profile `vivanti`) is **shared with other developers**. Every new resource uses the `articulate-ai-ib` / `articulate` prefix and lives under catalog `articulate_ai_ib`. Jobs and other taggable resources carry the tags `project=articulate-ai`, `owner=ishan.bhalla@vivanti.com`, `env=dev`.
- **Never drop, delete or overwrite a workspace object the user did not create.** Check its owner or creator first, and ask if it isn't the user's.
- Ask before creating, deleting or deploying workspace resources. Always pass `--profile` explicitly.
- Manage resources through the bundle (`databricks.yml` + `resources/*.yml`) rather than creating them by hand.
- Don't print or commit `articulate-ai-ib/.env`.

## Conventions and invariants

- Lakebase schema changes go in a new numbered file in `setup/lakebase/`. Every statement must be idempotent. Don't edit migrations that have already been applied.
- Prompts are versioned. To change a prompt, add a new version (e.g. `feedback_v2.md`) instead of editing one in use.
- The feedback rules are enforced in code, not trusted from the model: exactly 10 categories, whole-number scores from 1 to 5, and every quote found word for word in the transcript. Delivery metrics are measured, never generated by the model. Keep these checks and their tests (`processing/tests/test_feedback_rules.py`) in step.
- Each job step updates `sessions.status` and `current_step`, which the app polls. A new step must do the same and record its own failure.

## Gotchas

- Serverless `spark_python_task` has no `__file__`.
- Every job task needs `disable_auto_optimization: true`. Otherwise serverless retries failed tasks, and the retries race the app's own Retry, which resets the session first.
- The job no-ops on an empty `session_id`. The AppKit jobs plugin exposes an HTTP trigger route that `server.extend` middleware can't block.
- Audio is decoded with `imageio-ffmpeg` because faster-whisper's PyAV decode breaks on serverless.
- Claude models on Databricks reject `temperature`. Don't send it.
- The admin check calls `/Me` with the forwarded token, because SCIM user search takes about 30s in this workspace.
- Don't add `user_api_scopes` to the app. `iam.current-user:read` is only granted by default when no scopes are declared.
- The Lakebase schema `articulate` is owned by the user. After recreating the app, re-run `setup/lakebase/grant_app.py` to give its service principal access.
- The feedback LLM step takes 150–400s, so allow for that in timeouts and polling.
